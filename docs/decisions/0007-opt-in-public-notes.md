# 0007. ひとことメモは、本人が「みんなに見せる」を選んだものだけ公開する（既定は非公開。規約の改定を先に知らせ、2段階で出す）

- Status: Accepted（機能と進め方は決定。適用日は CEO の選択待ち: 下の「適用日」）
- Date: 2026-10-07
- Decider: CEO（2026-10-07、AI PM の提案に「他の人のメモも見えるようにして」と承認。公開する範囲と個人情報の扱いが変わるので PROCESS.md §1 のエスカレーション条件にあたる）。細部は AI PM（下の「AI PM の判断」。CEO が異を唱えない限りこのまま）
- Issue: [#17](https://github.com/mizuki-majima/try_something_new/issues/17)（PILOT 中の例外。[#16](https://github.com/mizuki-majima/try_something_new/issues/16) の「詳しく見る」の続き）

## Context

- これまでひとことメモは本人だけが見られ、利用規約・プライバシーポリシー・設定の説明でも「公開しない」と書いていた。PILOT 中に CEO が他の人のメモも読めるようにしたいと依頼し、AI PM は「本人が『みんなに見せる』を選んだメモだけを出す。すでに書かれたメモが勝手に公開されることはない」と提案した。CEO はこれを承認した（2026-10-07）
- 本番には PILOT の参加者のメモがすでにある。どれも「自分だけに見えます」と書かれた欄に書いたもの
- 1日組の一覧の GSI（gsi1）は、チャレンジの全属性を射影している（`infra/lib/thirty-days-stack.ts` の `ProjectionType.ALL`）。メモはいまも索引に入っていて、公開の形を作る許可リスト（`apps/api/src/db/cohorts.ts` の `toCohortMember`）だけが壁になっている
- 前の版の画面（ホーム画面アプリのキャッシュ、開いたままのタブ）は「自分だけに見えます」と出し続け、送信待ち（outbox）も前の形で送ってくる
- 利用規約の「規約の変更」は「変えるときは、変更後の内容と、変更が効力を持つ日を、その日より前に本サービスの画面でお知らせします」と約束している

## Decision

### 決まり（不変条件）

その日のひとことメモが公開されるのは、次がすべて成り立つときだけ:

1. 保存されている印の `shownNote` が、いまの `note` と同じ文面である（本人が見て選んだ文面にだけ同意する）
2. そのメモが、今の公開テキストの決まりに合う（URL 禁止・文字数と UTF-8 の上限。整えても文面が変わらない）
3. そのチャレンジが1日組に出ている（非表示でも、読み込んだままでもない）
4. 持ち主の進捗公開が ON（メモを返す API は、チャレンジと持ち主の設定を強い整合で読み直す）

- `shownNote` を書けるのは、新しいルート `PUT /api/challenges/:id/stamps/:day/visibility` だけ。ほかの書き込みは消すか触らない（文面が変わる保存は「自分だけ」に戻す。バックアップの読み込みは選択を引き継がない）
- `shownNote` が無ければ非公開。**今あるデータは移行も置き換えもせず、すべて非公開のまま**
- 読むたびに確かめるので、どこかの経路で文面が変わっても、公開されない側に倒れる
- 見せるのは1人1日30回まで。戻すのは数えず、いつでもできる
- 写真は今までどおり端末の中だけ（Do Not Build）。メモへの返信・コメント・反応は作らない

### AI PM の判断（CEO が異を唱えなければこのまま）

1. 見せたメモは「みんな」のほかの表示と同じく、アカウントのない人も含めて誰でも見られる（`GET /api/cohorts` が公開なのと同じ）
2. 見せる選択は、進捗公開の OFF → ON や、モデレーターの「復元」のあとも残る（OFF の間と非表示の間は見えない）
3. 振り返ったあとのチャレンジのメモも、見せる・戻すができる
4. モデレーションはその人の表示ごと（1日組の表示 `member` の通報・非表示）。メモ1件ずつの非表示は作らない
5. 見せる・戻すは、つながっているときだけ（送信待ちに入れない）。オフラインの持ち主は、つながるまで戻せない

### 2段階で出す

- **1段目（お知らせ。動作は変えない）**: 改定した利用規約とプライバシーポリシー（改定日・適用日つき。両方のページの上に「改定のお知らせ」）と、全画面の上の「お知らせ」の帯（閉じられる。適用日の14日後に自動で消える。利用規約とプライバシーポリシーのページでは、ページの上の「改定のお知らせ」で代える）。変わる文はどれも「（適用日）から」と書き、適用日の前にも後にも正しい内容にする（適用日より前は、ひとことメモは公開されない）
- **2段目（機能）**: 適用日以降にマージしてデプロイする。コードに日付の判定は入れず、マージの時期で決める（ほかの変更で main をデプロイしても、機能が先に出ることがない）
- 理由: 規約の「規約の変更」の約束を守るため。機能と規約の改定を同時に出すと、効力を持つ日より前に知らせられない。参加者が、見せる前に何が変わるかを知る時間もとれる。同時に出す案は、この約束を破るので選ばなかった

### 適用日（CEO の選択待ち）

- 改定日は 2026-10-07。適用日は CEO の選択待ち（CEO に示した選択肢: **A 2026-10-10**（3日前の告知、推奨）／ **B 2026-10-14**（7日前の告知））。1段目は A（2026-10-10）で下書きしている
- **告知の期間は、本番に出た日から数える**。1段目をデプロイしたら、本番でお知らせの帯と改定後のページが出ているのを確かめ、その日付を記録する。CEO が選んだ告知の日数に足りない日にデプロイすることになったら、デプロイの前に `EFFECTIVE_ON` を後ろにずらす
- **2段目は、CEO が適用日を選び、1段目が本番に出て、適用日を迎えるまでマージしない**
- 日付はコードでは `apps/web/src/lib/legal.ts` の `EFFECTIVE_ON` の1行だけ（規約・プライバシーポリシー・お知らせの帯はここから読む。テストもここから読み、A と B のどちらかであることと、改定日から3日以上あることを確かめる）。文書では、この ADR・PRODUCT.md・ROADMAP.md・CHANGELOG.md に書いている。B に決まったら、これらを一緒に直す
- 参加者に直接知らせるかは CEO の任意（画面のお知らせと日付つきの規約で、規約の約束は満たす。AI は参加者に連絡しない）

### 選ばなかった案

- 選択を真偽値で持つ: 文面が変わる経路が将来増えたとき、本人が見ていない文面が公開されうる。選んだ文面の写しで持てば、合わなければ非公開になる
- 一覧（`GET /api/cohorts`）に文面を入れる: 一覧は GSI の結果整合で、戻したときにすぐ消えない。文面は別のルートで強い整合で読み、一覧には見せている数だけを載せる
- 印の保存のルート（`PUT .../stamps/:day`）で選択も送る: 前の版の画面や送信待ちの再送が、戻したあとに選択を書き戻せる。選択を書くルートを分け、前からのルートは選択を消すことしかできないようにする

## Consequences

- 今あるメモは何もしなくても非公開のまま。デプロイで書き換えるデータはない（デプロイの前後で参加者のデータの件数が変わらないことを確かめる。#17 の受け入れ条件）
- 前の版の画面は新しいルートを呼ばないので、何も公開できない。別の端末で見せたメモに、前の版の画面が「自分だけに見えます」と出す残りのずれは、お知らせの期間で小さくする
- ルートが2つ増え、「詳しく見る」を開くたびに1回読む。見せる・戻すはオフラインではできない
- **戻すとき（ロールバック）**: 前のビルドを入れ直せばよい。前の API はメモを外に出さず、印の保存で `shownNote` を付けない。残った `shownNote` は使われず、もう一度新しい版にしたときは、文面が変わっていないもの（＝本人が選んだもの）だけがまた見える。改定後の規約とプライバシーポリシーは「選んだものだけ公開」なので、機能を戻しても食い違わない（公開されるものが減るだけ）。1段目は表示だけなので、戻す必要はない
- 見直す条件: メモ1件ずつの非表示が必要になったら、`MOD#<chId>` に印を足す（`notesHidden`）。参加者から苦情や戸惑いがあれば、CEO に報告して既定や文言を見直す。Gate 7 の基準は変えない
