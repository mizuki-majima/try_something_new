# 0008. 見た目を「白いノート」にし、メニューを4つにする（PILOT 中の例外。データ・API・公開範囲・URL は変えない）

- Status: Accepted（本番へのデプロイは、CEO が 360px のライトとダークの見本を見て承認してから）
- Date: 2026-10-08
- Decider: CEO（2026-10-08 の依頼:「手書きっぽい」「白をベースに」「夜で暗いとみにくい・色がきつい」「サステナブルなデザイン」「ページ構成をわかりやすく」）。細部は AI PM（下の「AI PM の判断」。CEO が異を唱えない限りこのまま）
- Issue: [#20](https://github.com/mizuki-majima/try_something_new/issues/20)（`phase:pilot` `type:design` `priority:p1` `status:needs-ceo`。PILOT 中の例外。[#16](https://github.com/mizuki-majima/try_something_new/issues/16)、[#17](https://github.com/mizuki-majima/try_something_new/issues/17) と同じ書き方）

## Context

- 見た目は 2026-10-06 の CEO 指定でネオ・ブルータリズム（太い黒線・ずらし影・原色・Dela Gothic One。SPEC FR-21 と [docs/design.md](../design.md) が名前で定めていた）
- ダークは背景と文字だけを入れ替え、黄・ミント・朱の大きな塗りに黒い文字のままだった。夜に端末がダークだと、選択中のタブ・きょうのマス・チップが明るいブロックになる。CEO の「夜で暗いとみにくい・色がきつい」の原因と見られる
- フォントは2ファミリー・4ウェイト（Dela Gothic One 400、Zen Kaku Gothic New 400/700/900）で、配る woff2 は 486 ファイル・5.74MB
- メニューは5つ（きょう・レシピ・ガチャ・みんな・記録）。毎日使うのは きょう だけで、レシピとガチャは「次の30日を選ぶ」という同じ用事に2つのタブを使っていた。設定は歯車のアイコンだけで、通知・ホーム画面・引き継ぎ・公開の設定がそこにある。チャレンジの画面の戻るリンクはいつも「きょう」だった
- PILOT 中の決まりは「機能を足さず、バグと運用だけ直す」（PRODUCT.md Current Goal）。2026-10-07 に招待を送っており、参加者はいまの画面を知っている。招待文は「みんな」「設定」「引き継ぎコードを発行」「バックアップ」「通知を許可する」を名前で書いている

## Decision

### 変えるもの

- **見た目**: 「白いノート」。生成りの紙と白いカード、墨色の文字、1px の線と余白、手書きの見出し（Klee One 600）、淡いセージの緑と印の朱の2色。影・太い黒枠・方眼・傾き（印を除く）をやめる。ダークは「夜のノート」（暗い灰の紙、温かい白の文字、明るい大きな塗りなし）。トークンとコントラストの表は [docs/design.md](../design.md)
- **フォント**: Klee One 600 だけを自前で配信（`@fontsource/klee-one`、OFL-1.1）。見出し・ブランド・印・大きな数字だけに使い、本文・ボタン・入力・メモは端末のフォント。Save-Data と `prefers-reduced-data` のときは読み込まない
- **メニュー**: 4つ（きょう／えらぶ／みんな／記録）。えらぶ は `/recipes` を開き、レシピとガチャを「えらびかた」の切り替えで行き来する。設定はヘッダーに文字つきで出す。チャレンジの画面の戻るリンクとタブの選択は、チャレンジの状態（振り返り済みなら 記録）で決める
- **画面の並び**: きょう（ヒーローの3つの操作に強弱、「もうひとつ試す？」を控えめに後ろへ）、記録（終わった30日 → まとめ → メモ、続けている30日は きょう への1行）、設定（表示を一番上に）
- **シェアカード・`/s/:id`・アイコン・OGP** も同じ見た目に（新しく作るものだけ。すでに作ったカード画像とホーム画面に追加済みのアイコンは古いまま）

### 変えないもの（不変条件）

- データ、API の振る舞い、公開する範囲、URL（`/recipes` `/recipes/:id` `/recipes/new` `/gacha` `/together?tab=` `/settings#…` などすべて開き、同じページを出す）
- 参加者が頼りにしている文言と、E2E が使う名前（「メニュー」「記録」「みんな」「設定」「このサイトについて」、各画面の h1、「詳細・メモ」「振り返る」など）
- テーマの選び方（FR-21）: 端末に合わせる（初期値）／ライト／ダーク
- 「みんな」の公開される範囲の説明の位置（タブの前）と文面。開示の目立ち方を下げない
- 44px のタップ領域、両方のテーマでの WCAG AA、CSP（自前のフォントだけ）

### AI PM の判断（CEO が異を唱えなければこのまま）

1. 既定のテーマは「端末に合わせる」のまま（A）。夜に端末がダークなら新しい落ち着いたダークになる。全員をライトにする案（B）は FR-21 の変更になり、夜に白い画面になる。CEO は見本を見て B に変えられる（`lib/theme.ts` の `getThemePref` が返す既定値を変えるだけ）
2. メニューは レシピ と ガチャ を まとめた4つ。名前は「えらぶ」。どちらの URL もそのまま開く
3. 時期: CEO が見本を承認したらデプロイし、2026-10-24 ごろまでに出す。11/1〜11/30（1日組の期間）は UI を変えない
4. 参加者に見た目の変更を知らせない（招待文にある名前はすべて残る。顧客への連絡になるので、知らせるなら CEO が決める）
5. 手書きは見出し・ブランド・印・大きな数字だけ（Klee の部分ファイルは Zen の約2倍あるので、本文やメモに使うと初回の転送量が増える）
6. 「みんな」の公開の説明は今の位置（タブの前）と文面のまま。ページの下へ移す案はとらない

### 選ばなかった案

- ネオ・ブルータリズムのままダークの色だけ直す: 「白をベースに」「手書きっぽい」に応えない
- 5つのメニューのまま見た目だけ変える: 同じ用事に2つのタブを使う分かりにくさが残る
- 本文も手書き（Klee One 400 を足す）: 読みやすさと転送量が下がる
- 紙の質感の画像やテクスチャ: データ量が増える。罫線は CSS のグラデーションだけ

## Consequences

- 1つの PR の3つのコミット: (1) トークン・フォント・機械的な置き換え、(2) 部品とページの見た目・シェアカード・`/s/:id`・アイコン、(3) メニューと画面の並び。(3) はそれだけで戻せる（戻すと5つのメニューと前の並びになり、見た目は白いノートのまま）
- 配る woff2 は 486 ファイル（5,740,556 B）→ 124 ファイル（3,488,988 B）、フォントの CSS は gzip 122,516 B → 31,546 B、`apps/web/dist` は 7,064,270 B → 4,464,092 B。ページごとの転送量（DevTools）の前後は PR に書く
- 参加者の端末の Service Worker のフォントのキャッシュ（`fonts`）に、前のフォントの部分ファイルが残る（消すのは `sw.ts` の変更。#20 の残り）
- すでに作ったシェア用カードの画像と、ホーム画面に追加済みのアイコンは古い見た目のまま
- SPEC.md は v1.6（FR-21・UI・Architecture のフォント）、[docs/design.md](../design.md) は全面的に書き直した
- **戻すとき（ロールバック）**: 前のビルドを入れ直せばよい。データと API は変わっていないので、戻してもデータは失われない。`/s/:id` の見た目も API のデプロイで一緒に戻る
- 見直す条件: CEO が見本で既定のテーマや手書きの範囲を変えたいとき、参加者から読みにくい・見つからないという声があったとき。Gate 7 の基準は変えない
