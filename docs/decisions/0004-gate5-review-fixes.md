## Context

Gate 5（REVIEW → TEST、[#2](https://github.com/mizuki-majima/try_something_new/issues/2)）の独立レビューと、その指摘を反証しようとした検証で、次が確かめられた。

- **Critical**: バックアップの読み込み（`POST /api/me/import`）に回数・件数の上限が無く、作成の規則も通らない。匿名アカウント1つで「今月の組」を200件の宣伝で埋められ（CUF-3 が壊れる）、書き込み費用にも上限が無い
- **High**: 公開カード（`/s/:id`）を通報する手段が無い（FR-18 違反）
- Medium / Low: 非表示にしたカードの画像が公開されたまま、IPv6 で IP ごとの上限が効かない、使い捨てアカウント3つで何でも隠せる、origin-verify の入れ替えで数分 API が止まり送信待ちが捨てられる、PILOT の指標がチャレンジ単位、API のエラーのアラームがルートの 500 を見ていない、予算が共用アカウント全体を見ている、など

テスト用の環境（`https://d1zw3n37kpuo7t.cloudfront.net`）は誰でも開ける状態なので、PILOT の前に直す。

## Consequences

- 既存の環境は、更新の前に `node scripts/setup-secrets.mjs` を1回実行する（`ip-hash-key` と `origin-verify-send` を作る）。`npm run deploy` は `--check` でこれを確かめる
- 予算は費用配分タグ `Project` を有効にするまで $0 のまま。それまではアカウント全体の予算アラートが頼り
- 画像保存・SNS での共有は人に結びつかないので、PILOT の共有率は公開リンクを作った人だけで数える（低めに出る）
- **CEO に確認すること**: D12（お問い合わせの返信先として個人情報を180日持つ）。`status:needs-ceo` の Issue で Option A（いまのまま）/ B（欄をなくす）と推奨（A）を示す
- 見直す条件: PILOT で通報や読み込みの上限に当たって困る人が出たら、上限を見直す

## 再レビュー（2回目、2026-10-07）

### Context

D1〜D13 の修正（コミット fef7802）を別のエージェントが再レビューし、実際に動かして次を確かめた。

- **Critical（NF-1）**: 費用に上限が無い。`PATCH /api/me` は回数の上限なしに、ニックネームや進捗公開を変えるたびに本人のチャレンジを全部書き直す。文字の上限が UTF-16 の長さなので、結合文字を詰めた「1文字」で約 1.5KB 保存できる。読み込みですぐに大きな項目を200件持てる。テーブルにスループットの上限が無い。匿名アカウント4つで1時間 約 $10、最大 約 $100 になりうる（目標は月 $1）
- Medium: 消して読み込み直すと、止めたカードを公開し直せ、1日組から外したものも戻る（NF-2）。IPv6 の /64 では1軒（日本の IPoE は /56）で上限の256倍のアカウントを作れる（security-3）。1人が24時間寝かせた3アカウントで何でも隠せる（security-4）。作成の 429 をすべて「1日の上限」として捨てるので、API Gateway の一時的なスロットルで新しいチャレンジが消える（r2-web-1）
- Low: 読み込んだチャレンジの振り返り直しで判定の内訳がマイナスになる（NF-3）、IP の鍵が無いと公開の既定の鍵で動き続ける（NF-4）、同時の読み込みで上限を超える（NF-5）、origin-verify の手順 3 がデプロイの成否を見ていない・空の `ORIGIN_VERIFY` で確認が外れる（NF-6）、規約・通報画面・運用の文書が実際と違う（r2-web-2/3/6、r2-docs-1）

### Decision

| | 決定 | 選ばなかった案 |
|---|---|---|
| R1 | (a) `PATCH /api/me` でニックネーム・進捗公開を変えるのは1人1日10回（日本時間の日付） (b) 公開用の情報の書き直しは、中身が変わる項目だけ（読み込んだまま・非表示・公開しない終わったものは触らない） (c) 保存する文字は書記素の数に加え、UTF-8 で `max × 4 + 32` バイトまで (d) DynamoDB のテーブルと各 GSI にオンデマンドの最大スループット（読み込み 400・書き込み 100 ユニット/秒）を費用の上限として付け、スロットルのアラーム（`alertEmail` 指定時） | プロビジョンドに切り替える（普段の費用と運用が増える）、上限なしで予算のメールだけに頼る（タグを有効にするまで $0 のまま。気づくまでに費用が出る） |
| R2 | モデレーションをチャレンジの項目の外に残す: カードや1日組を非表示・削除するときに `MOD#<chId>` / `META`（gsi2 `AUTHOR#<持ち主>` でアカウント削除と一緒に消える。shareModerated・memberHidden）を書き、`POST /api/shares` と読み込みが見る。管理画面の復元で該当の印を外す | 止めた内容と同じ文面を探して止める（判定が難しく、誤検知する） |
| R3 | 判定の内訳は、STATS に足したチャレンジ（`counted: true`）の振り返り直しだけで移し替える | 内訳を毎回全件から数え直す（読み取りの費用が増える） |
| R4 | Lambda（`IP_HASH_KEY_PARAM` あり）では鍵が無い・読めないと起動しない（500 と `ApiErrors`）。既定の鍵はテストとローカルだけ | 起動ごとの乱数の鍵で動き続ける（気づけず、レート制限の数がコールドスタートごとに数え直しになる） |
| R5 | 読み込みは1人ずつ: ロック `LOCK#import#<uid>`（条件つきの書き込み、60秒、終わったら消す）。同時に来たものは 409「読み込み中です。少し待ってからもう一度」 | 書いたあとで数え直して超えた分を消す（消すまでの間、1日組に出てしまう） |
| R6 | `ORIGIN_VERIFY` が設定されていて値が無ければ全部拒否。`setup-secrets.mjs` の手順 3 は、デプロイ済みのスタック（`describe-stacks` の状態と `origin-verify-send` の ResolvedValue）と CloudFront（`get-distribution` の Status とオリジンのヘッダ）を AWS CLI で読み（読み取りだけ）、新しい値を送っているときだけ進む | 時間で待つだけ（デプロイが失敗・飛ばされても進んでしまう） |
| R7 | IP ごとの上限は IPv6 なら /56 で数える。アカウント作成は全体で1時間300件まで（429 とやさしい文面、警告ログ） | /48 で数える（同じプロバイダの別の家庭とまとめて数えるおそれ） |
| R8 | 自動非表示は、条件を満たす3人が2つ以上のネットワーク（IPv4 /24・IPv6 /48 の秘密鍵つきハッシュを通報者の印に保存）から通報したときだけ | 自動非表示をやめる（運営者が見るまで隠れない） |
| R9 | 送信待ちは、`Retry-After` が1時間（3600秒）を超える 429 だけ捨てる。`Retry-After` が無い・短い 429（API Gateway のスロットル）は待って再送。API の上限の 429 には必ず `Retry-After` | 書き込みの種類で決める（今回の不具合の原因） |
| R10 | 規約と通報の画面は「通報は運営者が確認する。自動の非表示は条件つき」。`/s/:id` にもフッター（このサービスについて・利用規約・プライバシーポリシー・お問い合わせ）。アカウント作成の 429 は画面の帯で見せる。deploy.md・AGENTS.md・test-plan をスクリプトの実際の順序（ビルド → `--check` → `cdk deploy`）と費用の上限に合わせる | — |

詳細は [SPEC.md](../../SPEC.md) v1.2（本文に R 番号）、運用は [docs/deploy.md](../deploy.md)。

### Consequences

- DynamoDB は荒らしでも1時間 約 $1.9（書き込み 約 $1.0・読み込み 約 $0.8。テーブルと GSI 3つが上限まで使われた場合）で止まる。代わりに上限に当たっている間は、ほかの人の書き込みも遅れる（API の SDK がやり直し、通らなければ 500。端末の送信待ちに残り、あとで送られる）。上限に当たると `DynamoThrottles` のメールで分かる
- 既存のテーブルへの上限の追加は、CloudFormation の更新で置き換えにならない（データはそのまま）
- DynamoDB 以外（CloudFront・API Gateway・Lambda・Logs）は、ステージの上限 20 rps で月 $170 前後までありうる。2xx か 429 で終わるので `Api5xx` は鳴らず、気づけるのは予算のメールだけ（費用配分タグの有効化が前提）。API Gateway のリクエスト数のアラームは今回は足さない（下の「見直す条件」）
- origin-verify の入れ替えの手順 3 には AWS CLI と、`cloudformation:DescribeStacks`・`cloudfront:GetDistribution` の権限が要る（デプロイできる認証情報なら持っている）
- IP のハッシュ鍵が無いままデプロイすると、API は止まる（500）。`npm run deploy` は `--check` で先に止めるが、`cd infra && npx cdk deploy` で直接デプロイするときは先に `--check` を実行する
- **まだ CEO に確認していないこと**: D12（お問い合わせの返信先）。`status:needs-ceo` の Issue はまだ無い。PRODUCT.md の Do Not Build の例外は、CEO が答えるまで暫定（AI PM が Issue を作る）
- 見直す条件: 上限（スループット・プロフィール変更・アカウント作成の全体の上限）に、荒らしではない利用で当たったら上限を見直す。予算のタグを有効にできない、または DynamoDB 以外の費用の荒らしが起きたら、API Gateway のリクエスト数のアラームを足す
